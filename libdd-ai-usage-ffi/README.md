# libdd-ai-usage-ffi

A C interface to [`libdd-ai-usage`](../libdd-ai-usage), so that an LLM gateway
or integration in any language emits the same usage and cost metrics from the
same provider responses: Go through dlopen, Lua through LuaJIT's FFI, Python
through ctypes or a native module. Rust callers use `libdd-ai-usage` directly.

The header is [`include/ai_usage.h`](include/ai_usage.h), generated by cbindgen.
The crate builds a `cdylib` and a `staticlib`, and depends on nothing but
`libdd-ai-usage` and `serde_json`, so it can be built and loaded on its own.

## Conventions

- Structured values are UTF-8 JSON. Every input is a pointer and a length.
- Output is written to a `ddog_ai_usage_Buffer` the caller passes by pointer and releases with
  `ddog_ai_usage_buffer_drop`. No structure is passed by value.
- Every call returns a `ddog_ai_usage_Status`: `OK`, `REJECTED` (the input broke a rule; a JSON
  output holds `{"error": {"code", "message"}}` with a stable code) or `INTERNAL` (a null
  pointer, or a panic that was caught; a panic never crosses the boundary).
- As in the rest of libdatadog, the C ABI carries no backward-compatibility guarantee across
  releases: pin a version.

## Functions

| Function | Does |
| --- | --- |
| `ddog_ai_usage_project` | One observation (`{profile, observation, deployment_attributes, metrics}`) to its Datadog series and issues |
| `ddog_ai_usage_batch_new` / `_add` / `_is_empty` / `_take_dogstatsd` / `_drop` | Collect projections over an export window and take them as DogStatsD datagrams of at most a given size, with constant tags |
| `ddog_ai_usage_parse_provider_response` | A whole provider response body (JSON, or buffered server-sent events) to the observation's usage members, the model and service tier, how it ended and its `error.type` |
| `ddog_ai_usage_stream_new` / `_feed` / `_finish` / `_drop` | The same for a stream read as it passes through, in chunks that may end anywhere |
| `ddog_ai_usage_provider_name` | A gateway's or SDK's provider name to `gen_ai.provider.name` |
| `ddog_ai_usage_error_type` | An error name and HTTP status to `error.type` |
| `ddog_ai_usage_provider_ids` | Provider response headers and Bedrock model ARNs to the account and project attributes |
| `ddog_ai_usage_pack_dogstatsd` | DogStatsD lines to datagrams |
| `ddog_ai_usage_datadog_tag_value` | A value as Datadog stores it in a tag |
| `ddog_ai_usage_is_service_tier` / `_is_deployment_value` / `_is_person_identifier` | The grammars of a service tier, a deployment attribute value and `user.id` |

Usage formats are `auto`, `openai_chat`, `openai_responses`, `anthropic`,
`gemini` and `gemini_openai_compat`.

## Example

```c
#include "ai_usage.h"

const char *request =
    "{\"profile\": \"gen_ai.client.provider_attempt@0.1.0\","
    " \"observation\": {\"operation_name\": \"chat\", \"provider_name\": \"openai\","
    " \"duration_seconds\": 0.4, \"streaming\": false, \"observation_point\": \"gateway\"}}";

ddog_ai_usage_Batch *batch = NULL;
ddog_ai_usage_batch_new(&batch);

ddog_ai_usage_Buffer out = {0};
if (ddog_ai_usage_batch_add(batch, (const uint8_t *)request, strlen(request), &out) !=
    DDOG_AI_USAGE_STATUS_OK) {
  /* out holds {"error": {"code", "message"}} */
}
ddog_ai_usage_buffer_drop(&out);

/* At each flush: {"datagrams": [...]}, each ready for one send. */
ddog_ai_usage_batch_take_dogstatsd(batch, (const uint8_t *)"env:prod", 8,
                                   ddog_ai_usage_UDP_MAX_PAYLOAD, &out);
ddog_ai_usage_buffer_drop(&out);
ddog_ai_usage_batch_drop(batch);
```

## Header

After changing the interface, regenerate the header:

```sh
UPDATE_HEADER=1 cargo test -p libdd-ai-usage-ffi --test header
```
